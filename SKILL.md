# Meeting Transcribe

Локальная транскрипция и анализ записей созвонов на Mac (Apple Silicon). Оптимизирован под русскоязычные встречи 30 минут – несколько часов.

## Запуск в агенте

Общий workflow для Claude Code и Codex (приложение и CLI). Смысловую сверку и отчёт выполняет активная модель агента, включая Astra, если она выбрана пользователем. Отдельный OpenAI API, ключ или фиксированный ID LLM не нужны; `large-v3` ниже — модель локального распознавания Whisper, а не модель Codex.

Пути ресурсов `scripts/`, `references/` и `assets/` отсчитываются от каталога **этого `SKILL.md`**, а не от рабочего проекта пользователя. Перед запуском определи абсолютный каталог скилла из пути загруженного файла. Выполняй примеры с рабочим каталогом скилла либо подставляй абсолютный путь к `scripts/...`. Исходную запись, `--output-dir` и все созданные JSON/Markdown-файлы для `render`, `normalize` и `plan` передавай абсолютными путями. Артефакты по умолчанию сохраняются рядом с записью; для проверочного прогона используй отдельный `--output-dir`, чтобы сохранить прежние результаты. Review, расхождения и отчёт сохраняй в том же выбранном каталоге результатов.

Инструкции пользователя имеют приоритет над рекомендациями скилла. Используй уже названные путь, язык, параметры и согласие в текущей задаче; не переспрашивай их. Выполняй все независимые шаги до результата. Если расхождений нет, сразу пиши отчёт. Если они есть, подготовь полный список для проверки человеком; по запросу на предварительный отчёт или тест сохрани отчёт с явными неподтверждёнными ID, не выбирая правильную формулировку. Вопросы нужны для отсутствующих существенных данных и подтверждения спорных фактов, а не для повторного разрешения начать работу.

Нужен агент с доступом к локальным файлам и запуску Python/ffmpeg. В удалённой среде сначала проверь доступность записи, интерпретаторов и моделей: путь на компьютере пользователя сам по себе не делает файл доступным в облаке.

`setup_check.py` и `dual_transcribe.py` сами выбирают venv. Низкоуровневый `transcribe.py` проверяет пакеты только в запустившем его Python: во всех прямых примерах ниже, включая `--analyze` и `--diarize-only`, вместо `python3` используй путь «Python для Whisper» из `setup_check.py`. Одна переменная `WHISPER_PYTHON` не переключает интерпретатор прямого вызова. Для whisper.cpp без диаризации системного `python3` достаточно.

## Что делает

1. Проверяет исходную запись через `ffmpeg`/`ffprobe`.
2. Для русской речи запускает **два полных независимых прохода**: GigaAM v3 и локальный Whisper; для другой речи — только Whisper.
3. Сопоставляет две русские транскрипции по таймингам и передаёт различия активному LLM для смысловой классификации.
4. Показывает человеку обе версии и точный интервал исходной записи; ничего не исправляет до явного ответа.
5. Для Whisper всегда использует максимальную `large-v3`, не предлагает выбор размера модели и при установке сразу скачивает её. Бэкенды с beam search запускают beam=5; MLX остаётся только последним greedy-fallback.
6. **Опционально** диаризирует спикеров (см. ниже — по умолчанию выключено).
7. После разрешения критических расхождений пишет отчёт по шаблону `assets/report_template.md`.

> **Фиксированная политика модели:** не спрашивать «fast/balanced/quality» и не выбирать модель по длительности записи. Штатный чекпоинт всегда `large-v3`; менять можно только технический бэкенд исполнения.

Бэкенд выбирается автоматически в порядке: `whisper-cpp` → `faster-whisper` → `mlx-whisper`; MLX остаётся последним fallback без beam search. Детали — в `references/backends.md`, установка — в `references/setup.md`.

## Выбор движка

**Для русскоязычных записей дефолт — полный двойной проход:** GigaAM v3 (`v3_e2e_rnnt`, официальный пакет Сбера) + максимальная Whisper `large-v3`. GigaAM может потерять отрицание или транслитерировать термин; независимый Whisper нужен не как источник автоматически «правильных» слов, а как сигнал расхождения.

Whisper остаётся нужен:
- для нерусских записей и записей с большой долей английской речи;
- полным независимым проходом для сверки русских записей;
- когда нужен гранулярный `.srt`;
- если GigaAM не установлен, а пользователь не хочет его ставить.

Если пользователь не назвал движок явно: русская запись → двойной workflow ниже; другая речь → Whisper-workflow. Один движок для русской записи запускать только по явной просьбе пользователя либо после явного предупреждения, что сверка недоступна.

### Транскрипция через GigaAM

```bash
~/.venvs/asr/bin/python scripts/gigaam_longform.py "<путь>" --device mps   # CUDA: --device cuda, CPU: --device cpu
```

**Запускай интерпретатором того venv, где установлен gigaam** (по `references/setup.md` это `~/.venvs/asr`; если venv в другом месте — подставь его путь). Голый `python` вне venv упадёт с `ModuleNotFoundError: torch`.

Скрипт сам нарезает запись Silero VAD-ом по паузам под лимит энкодера GigaAM (~25 сек; жёсткий предел чанка — 30 сек) — HF-токен не нужен: в свежих версиях gigaam используется штатный `vad_backend="silero"`, в старых скрипт подменяет VAD самостоятельно. Отдельный запуск оставлен для диагностики; штатный русский workflow использует оркестратор ниже.

### Двухмодельная сверка русскоязычных записей

1. Preflight по записи — он нужен и здесь, а не только в одиночном workflow:

```bash
python3 scripts/transcribe.py "<путь>" --analyze
```

Из JSON взять `analysis.recommendation`: `backend` и флаг `no_condition_on_previous_text`. Показать пользователю длительность, оценку времени и найденные риски (`recommendation.reason` — готовая фраза).

2. Запустить оба ASR на **всей** исходной записи:

```bash
python3 scripts/dual_transcribe.py run "<путь>" --whisper-backend <recommendation.backend>
```

**Если `recommendation.no_condition_on_previous_text == true` — добавить `--no-condition-on-previous-text`.** Флаг передаётся Whisper-половине и лечит залипания после длинных тишин; без него длинная запись с паузами даёт поток ложных расхождений.

Другие параметры:
- `--initial-prompt "Участники: … Термины: …"` — если пользователь назвал имена или проектный жаргон, повышает точность Whisper по ним.
- `--diarize` (плюс при необходимости `--diarizer`/`--num-speakers`) — только по явной просьбе. Спикеры считаются **один раз после обоих проходов** и раскладываются по обоим транскриптам, поэтому метки `SPEAKER_00`/`SPEAKER_01` в версиях GigaAM и Whisper означают одного и того же человека: расхождение можно показывать вместе с тем, кто это сказал.
- `--gigaam-device mps|cuda|cpu` — явный override, обычно не нужен: устройство определяется автоматически.
- `--parallel` — запускать движки одновременно. **По умолчанию они идут по очереди (GigaAM, затем Whisper), и менять это без причины не нужно.** На машине с общей памятью параллельный запуск замерялся в 12.7 раза медленнее последовательного (1:53:48 против 8:57 у Whisper на 16 ГБ), а выигрывает он в лучшем случае время более быстрого движка — около минуты на 24-минутной записи.

Интерпретаторы скрипт выбирает сам: GigaAM — из `GIGAAM_PYTHON` либо `~/.venvs/asr`, Whisper — из `WHISPER_PYTHON`, либо `~/.venvs/whisper`, либо текущий python3. Если `--analyze` сообщил, что бэкендов нет, а пользователь уверен, что ставил их в venv, — проверить `WHISPER_PYTHON` (см. `references/troubleshooting.md`), а не переустанавливать пакеты.

Команда публикует артефакты только после успешного завершения обоих процессов:

- `<имя>.gigaam.transcript.{json,md,srt}`
- `<имя>.whisper.transcript.{json,md,srt}`
- `<имя>.comparison.json`
- `<имя>.review-template.json`
- `<имя>.gigaam.log`, `<имя>.whisper.log` — полные логи проходов (при падении: `<имя>.*.failed.log`, транскрипты не публикуются)

3. Прочитать `references/discrepancy-review.md`, оба полных JSON-транскрипта и все элементы `candidates` из comparison JSON. Скопировать review-template в `<имя>.review.json` и дать решение по каждому кандидату строго по контракту; неполный review не рендерится.

4. Отрендерить проверенный результат:

```bash
python3 scripts/dual_transcribe.py render "<имя>.review.json"
```

5. Показать пользователю `<имя>.disagreements.md`. Для каждого расхождения там должны быть точный интервал исходной записи, обе версии дословно, категория и причина важности. Критические показывать первыми.

6. **Не выбирать версию автоматически.** Не создавать аудиофрагменты и не предполагать наличие плеера в чате. Попросить пользователя самостоятельно прослушать указанный интервал в исходной записи и сообщить правильную формулировку.

7. Применять подтверждённую человеком формулировку только после явного ответа, сохраняя сырые транскрипты. До ответа считать зависимые решения, сроки, числа и цитаты неподтверждёнными. Если расхождений нет, переходить к отчёту сразу; предварительный отчёт по запросу допускается с перечислением нерешённых ID.

### Словарная сверка терминов (после расхождений)

Запускать **только после** того, как расхождения зафиксированы в `<имя>.disagreements.md`: словарь правит написание терминов и не должен скрыть сырой diff. Шаг опциональный — он окупается на записях с англицизмами и проектным жаргоном.

```bash
python3 scripts/hybrid.py normalize "<имя>.gigaam.transcript.json" --dry-run
python3 scripts/hybrid.py plan "<имя>.gigaam.transcript.json"
```

**Что с этим делать — важно, иначе шаг бесполезен:**

- Вывод `normalize --dry-run` — это **глоссарий записи**: список пар «как услышано → канон». Использовать его, когда пишешь отчёт: в тексте отчёта термин писать канонически (`prompt`, `Guardrail`, `GitHub`), чтобы одна сущность не выглядела тремя. Цитаты при этом оставлять дословными.
- Блок «требуют решения» (`policy: "suggest"`) — это термины, омонимичные русским словам («аппы», «рага»). Скрипт их никогда не заменяет. Если такой термин влияет на решение или action item — спросить пользователя.
- Вывод `plan` — ранжированный список мест, которые словарь не чинит: латиница вне белого списка, гомоглифы, низкая уверенность декодирования, разнобой написаний одного термина. Это вход для вопросов пользователю, а не список автоправок.

Запуск `normalize` без `--dry-run` создаёт `<имя>.gigaam.transcript.normalized.json`. **Этот файл — вспомогательный, для поиска и группировки упоминаний; он не заменяет транскрипт и из него нельзя цитировать.** Нормализация приводит словоформы к одной основе, поэтому «промты» и «промтом» превращаются в `prompt` — для подсчёта упоминаний это правильно, для русского текста цитаты — нет. Исходный артефакт не перезаписывается.

Нечёткое исправление искажённой латиницы включается только при наличии системного словаря английского (`/usr/share/dict/words`; на macOS есть штатно). Без него скрипт печатает предупреждение и правит лишь явные варианты из словаря — так он не превратит настоящее английское слово в термин.

## Когда включать диаризацию

**По умолчанию НЕ включай `--diarize`.** Запускай по запросу пользователя на разделение спикеров или атрибуцию («раздели по спикерам», «кто что сказал», «что Илья говорил про X?»). Длительность и число участников сами по себе не включают этот шаг.

Без диаризации не приписывай реплики людям по догадке. Диаризация может улучшить читаемость и атрибуцию, но требует отдельного прохода и проверки меток.

**Перед тем как ставить имена вместо `SPEAKER_XX`, проверь, что метки вообще соответствуют людям.** Если запись сделана одним микрофоном, а собеседники слышны через динамики, диаризатор может разделить акустические тракты вместо участников: несколько человек попадут в один кластер, и разметка будет выглядеть точнее, чем она есть. Быстрая проверка — прочитать по одному длинному фрагменту из каждого кластера: если в одном кластере встречаются реплики, которые не мог произнести один человек, атрибуцию по меткам не использовать и сказать об этом в отчёте. Подробности — в `references/backends.md` → «Ограничение: диаризация может разделять тракты, а не людей»; исторический замер там требует повторной проверки после исправления таймкодов.

Выбор диаризатора: pyannote (точнее, нужен `HF_TOKEN`) или resemblyzer (fallback, без токенов). Скрипт сам выберет `pyannote`, если токен есть. Подробности — в `references/setup.md` и `references/backends.md`.

У самого GigaAM диаризации нет: пакет использует pyannote только как VAD («где речь»), а не как speaker diarization («кто говорит»). Поэтому спикеров для обоих транскриптов считает `transcribe.py`, и запускается он тем интерпретатором, где стоит диаризатор (`WHISPER_PYTHON`). Отдельно этот шаг вызывается так:

```bash
python3 scripts/transcribe.py "<путь к записи>" --diarize-only \
  --apply-to "<имя>.gigaam.transcript.json" "<имя>.whisper.transcript.json"
```

Он перезаписывает `.json`, `.md` и `.srt` указанных транскриптов, добавляя спикеров, и не трогает текст.

## Workflow (одиночный Whisper)

Использовать для нерусской речи либо когда пользователь явно отказался от двойной сверки.

### Шаг 0. Проверить окружение (только при первом запуске)

```bash
python3 scripts/setup_check.py
```

После первой успешной транскрипции этот шаг можно пропускать.

### Шаг 1. Принять путь и проверить файл

`ls -la <path>`. Если файла нет — переспроси путь.

### Шаг 2. Preflight-анализ (длительность, риски и бэкенд)

Перед каждой транскрипцией:

```bash
python3 scripts/transcribe.py "<путь>" --analyze
```

(Добавь `--diarize` если пользователь просил диаризацию.)

Скрипт выведет JSON с двумя блоками:

- `options[]` — оценки времени `large-v3` на совместимых бэкендах.
- `analysis` — длительность, audio-properties, статистика тишин, громкость и рекомендация технического бэкенда. Поле `preset` всегда равно `quality`.

Поле `recommendation.reason` — это **готовая фраза для пользователя**, объясняющая выбор. Используй её в своём сообщении.

#### Шаг 2a. Если `available_backends` пустой — поставить бэкенд

Если в JSON пришло `"available_backends": []` (или `"options": []`) — текущий интерпретатор **не нашёл готовый Whisper-бэкенд**. Скрипт сам ничего не ставит. Сначала проверь выбранный `WHISPER_PYTHON` и существующие venv по `references/troubleshooting.md`; отсутствие пакета в системном Python не доказывает его отсутствие на машине. Если подходящего окружения действительно нет:

1. Определи платформу: `uname -sm`.
2. Не предлагай размеры модели. На Apple Silicon установи штатный `whisper.cpp`; на остальных платформах — `faster-whisper`, как описано в `references/setup.md`.
3. Сразу скачай максимальную `large-v3`. Не скачивай `large-v3-turbo` как альтернативу.
4. После установки повтори `--analyze` и продолжай.

#### Шаг 2b. Использование результата

Покажи пользователю длительность, оценку времени и найденные риски. Сразу запускай `large-v3` без вопроса о размере модели. Длинные тишины или большая доля тишины меняют только флаг `--no-condition-on-previous-text`, а не модель.

### Шаг 3. Запустить транскрипцию

```bash
python3 scripts/transcribe.py "<путь>" \
  --backend <recommendation.backend> \
  --language <язык-записи> \
  --yes
```

Язык бери из запроса (`en` для английского, `ru` для русского); для автоопределения передай `auto`. Модель и beam не передаются параметрами: скрипт всегда использует `large-v3` с beam=5 (кроме технического greedy-ограничения MLX). Бэкенд бери из `analysis.recommendation`.

**Если `recommendation.no_condition_on_previous_text == true`** — добавь флаг `--no-condition-on-previous-text`. Это критично для длинных записей с тишинами: иначе whisper после длинной паузы залипнет на одной фразе («Так./Видно?», «Продолжение следует…») и hallucination'ит её все оставшееся время через condition-окно.

Дополнительные параметры:
- `--diarize` — только по запросу (см. выше).
- `--diarizer pyannote|resemblyzer|auto` — обычно `auto` (дефолт).
- `--num-speakers N` — если пользователь знает точное число, повышает качество диаризации.

Скрипт сохранит рядом с исходником: `<имя>.transcript.json`, `<имя>.transcript.md`, `<имя>.transcript.srt`. Если падает — `references/troubleshooting.md`.

### Шаг 4. Прочитать транскрипт

Прочитай `.transcript.md`. Часовой созвон обычно ~10–20k токенов. Длинные записи (3+ часа) — читай частями. Для русского двойного workflow сначала полностью завершить сверку выше.

### Шаг 5. Написать отчёт по шаблону

Открой `assets/report_template.md` и заполни **все** секции на русском, в том же порядке: метаданные → TL;DR → темы → решения → action items → цитаты → открытые вопросы и риски → follow-ups. Неразрешённые расхождения явно помечать; не выдавать зависящий от них тезис за подтверждённый.

### Шаг 6. Сохранить отчёт

Сохрани как `<имя>.report.md` в выбранном каталоге результатов (`--output-dir`); по умолчанию — рядом с записью. Сообщи абсолютный путь и кратко перескажи 2–3 главных тезиса.

### Шаг 7. Проверить обновления скилла

**Только после того, как отчёт сохранён и путь озвучен.** Никогда до транскрипции и не между шагами: проверка не должна ни задерживать работу, ни вклиниваться в сверку расхождений.

```bash
python3 scripts/check_update.py
```

Скрипт молчит, если обновления нет, проверка выключена, сети нет или лимит запросов исчерпан — пустой вывод это штатный результат, докладывать о нём не нужно. Если он что-то напечатал, покажи это пользователю как есть и предложи обновиться.

**Обновление — только по явному согласию, каждый раз заново.** Согласие на прошлой встрече не считается. Получив «да»:

```bash
python3 scripts/check_update.py --update
```

Ничего не обновляй руками: не запускай `git pull`, `git checkout` или установку поверх каталога скилла сам. Скрипт отказывается работать, если каталог не под git, есть незакоммиченные локальные правки или скилл стоит плагином — в этом случае просто передай пользователю причину отказа. Скажи, что новая версия заработает со следующей сессии: текущая уже держит `SKILL.md` в контексте.

## Принципы отчёта

- Пиши **на русском** независимо от языка интерфейса.
- Опирайся на факты из транскрипта, не выдумывай.
- Тайм-коды в формате `[ЧЧ:ММ:СС]` к цитатам и важным моментам.
- Спикеры: с диаризацией используй метки `SPEAKER_00`/…; если из контекста ясны имена — мягко переименуй или спроси пользователя. Без диаризации — автора цитаты не указывай.
- Action items конкретные: не «обсудить роадмап», а «Ивану — собрать список рискованных тикетов к пятнице».
- Цитаты дословные (можно убрать «эээ» и обрезать тишины).
- Не заполняй секцию ради заполнения. Решений не было — так и пиши.

- `references/setup.md` — установка ffmpeg, Python, whisper.cpp, HF_TOKEN.

- `references/troubleshooting.md` — типичные проблемы.

- `VERSION`, `CHANGELOG.md` — версия установленной копии и история изменений.
