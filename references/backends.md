# Бэкенды, модели, пресеты

## Пресеты скорости/качества

Пресет — это пакет «модель + beam_size», подобранный для разумного компромисса.

| Пресет | Модель | beam_size | Когда выбирать |
|---|---|---|---|
| `fast` | `large-v3-turbo` | 1 | **Дефолт.** Большинство созвонов, рабочие встречи, планёрки. Длинные записи |
| `balanced` | `large-v3-turbo` | 5 | Только если плохое аудио или нужна точность beam search (требует `faster-whisper` — mlx beam search не реализован) |
| `quality` | `large-v3` | 5 | Юридически важные записи, интервью на публикацию, очень плохое аудио |

> **Важно про чекпоинты.** `fast`/`balanced` гоняют `large-v3-turbo` — это **дистиллят** полной `large-v3` с меньшим числом декодер-слоёв. На чистом рабочем созвоне разрыв в WER небольшой, и финальный meeting-отчёт между `fast` и `quality` практически не отличается — Claude восстанавливает структуру (решения, action items, имена, темы) даже из шумноватого транскрипта. **Но** на сложном аудио (тихая/эмоциональная речь, длинные паузы, перекрывающиеся голоса, низкий битрейт) разрыв заметен и реален — `quality` стоит включать не только ради «точных цитат», но и когда аудио объективно тяжёлое.
>
> Это **отдельная история** от «1–2% WER между бэкендами» — последнее про whisper.cpp vs mlx-whisper vs faster-whisper, гоняющие один и тот же чекпоинт. Там разница действительно техническая.

`beam_size` — параметр beam search в декодере. При beam=5 модель рассматривает 5 параллельных гипотез и выбирает лучшую (точнее, медленнее). При beam=1 — жадное декодирование (быстрее, иногда теряет редкие слова).

`large-v3-turbo` — дистилляция `large-v3`: меньше декодер-слоёв, в ~2 раза быстрее на инференсе. Качество близко к `large-v3` на «лёгком» аудио и расходится сильнее на «сложном» (см. выше). Для русского разрыв обычно умеренный, но именно на длинных паузах и тихих репликах turbo сильнее склонен к залипаниям и пропускам.

## Сравнение бэкендов (встроенные в скилл)

| Свойство | faster-whisper | mlx-whisper |
|---|---|---|
| Платформы | macOS, Linux, Windows | только Apple Silicon |
| Тип ускорения | CPU (CTranslate2 + int8) | MLX (unified memory, GPU) |
| Скорость на M4 (1 час аудио, balanced) | ~25 мин | ~6 мин |
| Качество русского | Отличное | Отличное |
| Beam search (beam>1) | ✅ работает | ❌ **не реализован** — `NotImplementedError`, скрипт автоматически откатывается на greedy с предупреждением |
| Поддержка pyannote | Да | Да (через faster-whisper) |
| Память (large-v3) | ~3 ГБ RAM | ~3 ГБ unified memory |

**Когда что выбирать:**
- На Apple Silicon с `fast` пресетом — `mlx-whisper` (быстрее), скрипт выбирает автоматически.
- На Apple Silicon с `balanced`/`quality` (нужен реальный beam search) — `--backend faster-whisper`.
- На Linux/Windows — `faster-whisper`.
- Если нужен максимальный контроль над `compute_type` (int8 vs float16) — `faster-whisper`.

## GigaAM v3 (интегрирован: `scripts/gigaam_longform.py`)

Официальная русская ASR-модель Сбера ([salute-developers/GigaAM](https://github.com/salute-developers/GigaAM)), чекпоинт `v3_e2e_rnnt` — с пунктуацией и заглавными. **На русских записях — первый кандидат**; Whisper — вторым проходом для сверки терминов (гибридная схема в `SKILL.md`).

Наши сравнения с whisper.cpp `large-v3` (quality, beam=5) на реальных записях:

| Запись | GigaAM v3 | Whisper large-v3 |
|---|---|---|
| Созвон 24 мин, 57% тишины | 2:53 (RTF 0.12), 2676 слов, **0 галлюцинаций** | 8:02 (RTF 0.33), 2462 слова, 6 галлюцинаций |
| Созвон 55 мин | ~9 мин | ~40 мин |
| Лекции, 5ч42м (6 файлов) | 12:17 (RTF ~0.036), **0 галлюцинаций** | ~50 мин, 125 галлюцинаций |

Время — фактическое по нашим прогонам на одной машине (M4); RTF Whisper заметно гуляет в зависимости от профиля тишины и загрузки системы, соотношение «GigaAM в 3–4 раза быстрее» держалось во всех трёх случаях.

Сильные стороны: скорость, устойчивость на тишине (Whisper на паузах вставляет «Продолжение следует…», «Субтитры сделал DimaTorzok»), русская доменная лексика («оркестратор» 3/3 против 0/3 у Whisper), «GigaChat» корректной латиницей.

Слабые стороны и что с ними делать:
- **Англицизмы транслитерирует на слух** (guardrail → «гардрейл/квартрейл», Langflow → «флогенты»). Для терминологически насыщенных записей — сверка написаний по Whisper-версии.
- **Лимит энкодера ~25 сек** — `gigaam_longform.py` сам режет запись Silero VAD-ом (HF-токен не нужен).
- Сегменты крупнее whisper-овских (~70 против ~270 на 24-мин записи) — `.srt` менее гранулярный; для субтитров бери Whisper.
- Смысловые ошибки редки, но случаются (в одном из сравнений потерялось отрицание, фраза читалась как противоположное решение) — ключевые решения сверяй вторым движком.

Установка — `references/setup.md` → «GigaAM v3» (важно: ставить с GitHub, PyPI-пакет отстаёт).

## Альтернативные ASR-инструменты (НЕ интегрированы в скрипт)

В бенчмарке на M4 эти альтернативы дали **более быструю** транскрипцию при сопоставимом качестве финального meeting-отчёта:

| Инструмент | RTF на M4 (clip) | Что особенного | Установка |
|---|---|---|---|
| **whisper.cpp** + Metal | ~0.06 (turbo) / ~0.18 (large-v3) | C++ порт Whisper, поддерживает beam search, очень быстр на Apple Silicon | `pip install cmake && git clone github.com/ggml-org/whisper.cpp && cmake -B build -DGGML_METAL=ON` |
| **gigaam-mlx (rnnt)** | ~0.08 | MLX-форк GigaAM (не официальный пакет — тот интегрирован, см. выше) | `pip install git+https://github.com/aystream/gigaam-mlx.git` |
| **gigaam-mlx (ctc)** | ~0.14 (на холодном запуске; warm rnnt быстрее) | то же, более тонкий вариант | как rnnt, флаг `--model-type ctc` |
| **T-one** | ~0.07 | Conformer 71M от Т-Банка, быстрее всего на M4. **Без пунктуации/заглавных** | `pip install git+https://github.com/voicekit-team/T-one.git && pip install miniaudio` |

Использовать как замену `transcribe.py` на шаге 3 (генерация транскрипта), затем шаги 4–6 идут как обычно (Claude читает `.transcript.md` и пишет отчёт по шаблону).

**Не рекомендуются на Apple Silicon:**
- **VOSK (Kaldi)** — RTF ~0.22, без пунктуации, шумнее остальных.
- **Qwen3-ASR-1.7B fp16** — самый медленный (RTF >>1 в нашем тесте) и единственный, кто **галлюцинирует уверенными именами** («Артём Тыгров», «Илья — юрист»), что портит финальный отчёт.

## Оценка времени (приблизительная, для M4)

Real-time factor (RTF) — отношение времени обработки к длительности аудио. RTF=0.1 означает «час аудио → 6 минут обработки».

| Бэкенд | quality | balanced | fast |
|---|---|---|---|
| faster-whisper | RTF ≈ 0.9 | RTF ≈ 0.40 | RTF ≈ 0.20 |
| mlx-whisper | RTF ≈ 0.20 | RTF ≈ 0.10 | RTF ≈ 0.05 |

Это табличные оценки в скрипте. Реальная скорость зависит от загрузки системы, длины пауз, плюс единоразовый оверхед на загрузку моделей (~6–8 секунд).

**Скрипт показывает оценку перед каждым запуском** (`--estimate-only` или интерактивный режим без `--yes`). После транскрипции в метаданных пишется фактический RTF — можно сравнить с табличным и при необходимости подправить таблицу под свою машину (см. `RTF_TABLE` в `scripts/transcribe.py`).

## compute_type для faster-whisper

| Значение | RAM | Скорость | Качество |
|---|---|---|---|
| `int8` | минимум | быстрее всего на CPU | минимально хуже |
| `int8_float16` | средне | быстро | как float16 |
| `float16` | средне | средне (нужна GPU/Metal) | эталон |
| `float32` | максимум | медленно | эталон |
| `auto` | — | сам подберёт | — |

На M4 без GPU-ускорения CTranslate2 разумнее всего `int8` или `auto` (по умолчанию выбирается `int8`).

## Диаризация: pyannote vs resemblyzer

| Свойство | pyannote 3.1 | resemblyzer |
|---|---|---|
| Точность (DER) | ~10–14% | ~18–25% |
| Пересекающаяся речь | Хорошо | Плохо |
| Короткие реплики (<1 сек) | Норм | Часто пропускает |
| Установка | pip + HF_TOKEN | pip |
| Регистрация | Нужна (бесплатно) | Не нужна |
| Скорость на M4 | RTF ≈ 0.12 + 25 сек на загрузку | RTF ≈ 0.05 + 8 сек на загрузку |
| Загрузка моделей | ~1 ГБ | ~17 МБ |

`--diarizer auto` (дефолт): pyannote если есть HF_TOKEN, иначе resemblyzer.
`--diarizer pyannote` или `--diarizer resemblyzer` — явно выбрать.
`--diarizer none` — отключить диаризацию (равносильно отсутствию `--diarize`).

## Параметры диаризации

- `--num-speakers N` — если **точно** знаешь количество спикеров, передай. Сильно повышает качество, особенно когда спикеров мало (2–3).
- `--max-speakers N` — верхняя граница автоопределения для resemblyzer (по умолчанию 6).

resemblyzer без `--num-speakers` подбирает k в диапазоне 2..max-speakers по silhouette score. Если лучший score < 0.10 — считается, что спикер один.

pyannote без `--num-speakers` определяет число спикеров своим алгоритмом (обычно точно).

## Подсказки по качеству

- **Шум, эхо, плохое аудио** — бери `quality` (large-v3 заметно устойчивее на сложном аудио).
- **Иностранные термины и имена** — Whisper иногда транслитерирует странно. После транскрипции сам Claude может подправить написание в отчёте, если знает контекст.
- **Очень длинные записи (3+ часа)** — `fast` для черновика + ручная проверка важных мест. Транскрипт всё равно сохраняется в файл; читай его частями.
- **Если слышишь, что результат хуже ожидаемого** — попробуй явно `--language ru` (вдруг auto-detect сбился) и `--num-speakers N` для диаризации.
