# Проверка формулировок и редакторская версия

Читай после смысловой сверки двух ASR, перед отчётом. Этот проход проверяет
**обе полные расшифровки**, включая согласные участки: оба движка могут одинаково
услышать «в пятницу, нет, в четверг». Самоисправление, окончательное решение
и неясная формулировка требуют отдельного внимания при подготовке отчёта.

Review выполняет активная модель агента. `quality_review.py` не вызывает LLM,
не отправляет текст в сеть и не определяет правильные факты алгоритмом.

## Подготовка

Сначала заполни обычный `.review.json` по `discrepancy-review.md`. Затем:

```bash
python3 scripts/quality_review.py prepare "/abs/meeting.comparison.json" \
  --discrepancy-review "/abs/meeting.review.json"
```

Получатся `.quality-manifest.json` и пустой `.quality-review.json`. Manifest
содержит полные тексты обоих ASR, индексы сегментов, блоки чтения `B001…`,
неразрешённые `D*`, подсказки о самоисправлениях и SHA-256 исходных артефактов.
Подсказки — ориентир для чтения, не полный список находок. Прочитай все блоки
обоих ASR с соседним контекстом, особенно на границах блоков. Не меняй manifest.

Comparison связывает исходные сегменты SHA-256 уже при сверке. Старые comparison
без `segments_sha256` отклоняются. Их можно пересоздать **без повторного ASR**:

```bash
python3 scripts/dual_transcribe.py compare \
  --gigaam "/abs/meeting.gigaam.transcript.json" \
  --whisper "/abs/meeting.whisper.transcript.json" \
  --source "/abs/meeting.mp4" --output "/abs/new-review/meeting.comparison.json"
```

Проверь новый semantic review перед `prepare`: не переноси прежние решения,
пока не убедишься, что кандидаты и оба текста остались теми же.

Основа редакторской версии по умолчанию GigaAM; `--base-engine whisper` выбирает
другую основу до review. Это выбор оформления: нерешённые расхождения любой
основы будут скрыты маркерами. Повторный `prepare` не стирает выполненный review;
для новой подготовки укажи отдельный `--output-dir`.

## Quality review

Сохрани в шаблоне `manifest_file` и `manifest_sha256`. В `reviewed_blocks`
перечисли каждый действительно прочитанный `B*` ровно один раз. Неполное покрытие
не рендерится. Если находок и правок нет, оставь `findings: []`, `edits: []`.

Новые содержательные находки записывай в `findings`. Для примера исходный текст
`В пятницу, нет, в четверг.` имеет 26 символов:

```json
{
  "id": "Q001",
  "kind": "self_correction",
  "span": {"start": 0, "end": 26, "from": "В пятницу, нет, в четверг."},
  "severity": "critical",
  "categories": ["date_or_deadline"],
  "review_reason": "Говорящий изменяет срок; нужно подтвердить окончательную формулировку."
}
```

`span.start/end` — индексы Unicode-символов Python в
`manifest.transcripts[base_engine].text`, граница `end` исключающая.
Скрипт проверяет точное равенство `text[start:end] == from`. Между исходными
сегментами находится один `\n`, поэтому находка может пересекать их границы.
Для точного вычисления offsets используй короткий Python-вызов; не угадывай.
Таймкоды скрипт получает сам из сегментов и явно обозначает эту точность.

Допустимые `kind`: `self_correction`, `ambiguity`, `other`; severity и categories
те же, что в `discrepancy-review.md`. Не записывай предпочтительный вариант
факта в finding. Не дублируй `D*` без новой причины: несколько IDs в одном
месте можно подтвердить одной точной правкой пользователя.

`edits` — только редакторские правки с полями `id: E001`, `kind`, `span`, `to`,
`review_reason`. Допустимы `punctuation`, `spacing`, `case`, `vocalization`.
Первые три сохраняют слова и числа; изменение латинского регистра также
блокируется, поскольку `mW` и `MW` различаются. `vocalization` может удалять
только бессмысленные «ээ», «аа», «ммм». «Ну», «нет», повторы слов, термины,
числа, сроки, исполнители и модальность не удаляются редакторским патчем.
Их содержательное изменение требует finding и ответа пользователя.

## Черновик и подтверждения

```bash
python3 scripts/quality_review.py render "/abs/meeting.quality-review.json"
```

Создаются `.quality-findings.json/md`, `.clean.md` и `.clean.changes.json`.
Покажи новые `Q*` вместе с нерешёнными `D*`, критические первыми. Укажи интервал
исходной записи; не создавай аудиоклипы без запроса. В черновике спорный участок
заменяется `[НЕ ПОДТВЕРЖДЕНО: D001, Q001]`. Для D скрывается консервативно весь
пересекающийся исходный сегмент. Это не означает, что весь сегмент ошибочен.
Редакторские правки внутри скрытого участка пропускаются и видны в журнале.

После фактического ответа пользователя сохрани его дословно. Применение требует
точной привязки к исходному тексту, поскольку D-интервалы включают соседний
контекст, а ответ может состоять из одного слова. Не заменяй весь D-интервал
коротким ответом. Расширенный `.human-resolutions.json` имеет вид:

```json
{
  "schema_version": 1,
  "manifest_file": "/abs/meeting.quality-manifest.json",
  "manifest_sha256": "SHA256_ИЗ_QUALITY_REVIEW",
  "resolutions": [
    {
      "candidate_id": "Q001",
      "confirmed_by": "user",
      "span": {"start": 0, "end": 26, "from": "В пятницу, нет, в четверг."},
      "confirmed_text": "В четверг."
    }
  ]
}
```

Вместо `candidate_id` можно указать `candidate_ids: ["D001", "Q001"]` для
одной подтверждённой правки. IDs должны существовать; span должен относиться
к ним, а патчи не должны пересекаться. `confirmed_text` не дополняй от себя.
При неоднозначной привязке уточни конкретную формулировку, не угадывай место.

```bash
python3 scripts/quality_review.py render "/abs/meeting.quality-review.json" \
  --human-resolutions "/abs/meeting.human-resolutions.json" --verified
```

`--verified` отклоняется при любом нерешённом ID. Если после полного review
находок нет, он работает без файла подтверждений: дополнительный вопрос
пользователю не нужен. При частичных ответах рендери без `--verified`; в отчёте
сохраняй нерешённые IDs и не подтверждай зависящие от них тезисы.

Статус verified означает завершённый процесс сверки, а не гарантию отсутствия
любых ASR-ошибок. `.clean.md` всегда редакторская версия **не для дословных
цитат**. Цитаты проверяй по raw и исходной записи. Raw не перезаписывается;
журнал хранит точные правки, таймкоды и происхождение подтверждений. Изменённые
исходники или устаревший manifest отклоняются до публикации результата.
