# Эксперимент с GigaAM Duo из Type

Отдельный добровольный эксперимент на macOS с установленным Type. Он не меняет
обычный запуск, `dual` или основной ASR. Скрипт использует внутренний native addon
приложения; это не официальный standalone SDK. Проверяется известная поставка
`type.v1.019.20260917`, модель `asr.gigaam_duo.v1.3`. Другая поставка завершается
ошибкой до запуска распознавания.

```sh
node scripts/duo_transcribe.cjs "/absolute/path/recording with spaces.wav" \
  --app /Applications/Type.app \
  --output-dir "/absolute/path/duo results" \
  --chunk-seconds 20 \
  --segmentation pause
```

Нужны Node.js, локальные `ffmpeg` и `ffprobe` в PATH; если их нет, скрипт проверяет
`Contents/Resources/bin` приложения. Ничего не устанавливается и не скачивается.
GUI Type не запускается. Пользовательский профиль и кеш Type не читаются.
Временный `modelRoot` ссылается только на bundled ASR, passthrough и core;
две обязательные записи каталога LLM содержат только метаданные, без весов.
Постобработка выключена (`llm_off`). Модели не копируются в репозиторий и не
расшифровываются. Временный PCM удаляется после завершения, включая ошибку.
Сообщения native runtime `Deferred submodel ... model.tar` ожидаемы для пустых
записей выключенных LLM; они не означают отказ ASR, если команда завершилась успешно.

Результат — `<исходное имя с расширением>.duo.transcript.json` и `.md` в указанной
папке. JSON имеет обычные `metadata` и `segments` с `start`, `end`, `text`;
точная модель, версия приложения и release сохранены в метаданных. Существующие
результаты не перезаписываются; при ошибке ASR итог не публикуется.

По умолчанию `--segmentation pause` ищет паузы локально в уже декодированном
16 kHz float32 PCM. RMS считается по окнам 20 мс; соседние окна не выше
−40 dBFS объединяются, интервал должен длиться не менее 250 мс. Порог абсолютный,
без нормализации записи. Чтение ограничено буфером 80 KiB; NaN и бесконечности
отвергаются. Новых моделей и зависимостей для поиска пауз нет.

`--chunk-seconds` задаёт ориентир (по умолчанию 20, допустимо 1–25 секунд).
Для очередного среза выбирается середина паузы, ближайшая к ориентиру, в окне
от `max(1, 0.6 × ориентир)` до `min(25, ориентир + 5)` секунд от начала чанка.
У длинной паузы берётся середина её пересечения с этим окном; при равном
расстоянии выбирается более ранний срез. Если паузы нет, используется ориентир
и граница помечается `forced`. Последний остаток целиком сохраняется в одном
чанке, если он не длиннее ориентира плюс 5 секунд и не длиннее 25 секунд.
Покрытие непрерывное: тишина не вырезается, перекрытия и пропуски не создаются.
Синтетическая тишина вокруг native input также входит в лимит 25 секунд.

Для контрольного прогона есть `--segmentation fixed`: прежние фиксированные
чанки без поиска пауз. В JSON `segments` остаётся `{start, end, text}`.
`metadata.segmentation` хранит метод, параметры RMS, число обнаруженных пауз и
число `forced_cuts`; массив `boundaries` содержит `end_sample`, `end`, `reason`
для каждого чанка. Причины — `pause`, `forced`, `final`; в fixed все внутренние
границы считаются `forced`. Список границ соответствует порядку `segments`.

Метки времени относятся **к чанкам, не к словам**. `words` не создаётся.
Энергетическая пауза — не речевой VAD: тихая речь может попасть под порог,
а фоновый шум — скрыть паузы и привести к фиксированному срезу. Сохранение всех
PCM-сэмплов не гарантирует сохранения смысла при распознавании; на границе всё
ещё можно потерять или испортить слово. Это также не диаризация. Сравнивать
с текущим ASR нужно на одном аудио: отдельно проверять русский текст, английские
названия и термины, числа и отрицания, обрывы на границах. Само имя Duo не
доказывает превосходство на встречах. Редактирование оговорок и стиля здесь
намеренно не включается.

Результаты сравнения fixed/pause с обычным GigaAM на пяти записях и контрольном
синтезе: [duo-evaluation.md](duo-evaluation.md). По этому прогону основной
backend не заменён: на реальной речи остаются непроверенные важные расхождения.

Type заявляет MIT на [сайте приложения](https://gigatype.app/), но отдельного
публичного SDK и model card Duo не найдено. Эксперимент зависит от внутреннего
ABI установленного приложения и не является обещанием независимой переносимой
поставки модели. Для открытого backend есть
[GigaAM Multilingual](https://huggingface.co/ai-sage/GigaAM-Multilingual), качество
которого на смешанной русско-английской речи также нужно измерять отдельно.
